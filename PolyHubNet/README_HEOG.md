# HEOG: фиксации и редактируемые номера — 30.10.2026

## Использование

1. Откройте PHS и остановите проигрывание. При наличии одноимённого файла `.analysis.json` разметка и параметры HEOG загрузятся автоматически.
2. Задайте Range (µV), нажмите Mark HEOG. Для разметки модель не требуется.
3. Красные линии обозначают выраженные скачки HEOG. Бледно-зелёные области обозначают сами устойчивые фиксации, включая короткие. Дополнительных заливок нет.
4. Находим первое событие включения ноты (окончание ноты и события других классов не подходят). Стартовой становится содержащая его устойчивая фиксация. Ей присваивается 41 по условию обхода от крайней левой ноты. Сам распознанный номер не используется как правильный ответ.
5. Более ранние фиксации не подсвечиваются и не нумеруются; сигнал и красные линии HEOG сохраняются. Дальше над каждой фиксацией отображается один номер. Автоматический черновик: `41→43→45→47→48→50→52→53→52→50→48→47→45→43→41→…`. Крайние ноты при развороте не дублируются. Нумеруются и фиксации без срабатывания ноты.
6. Проверьте черновик по фактическому выполнению задания. После лишнего перевода взгляда номера могут потребовать правки. Первая жёлтая метка выбирает только начало обхода; последующие ответы классификатора не задают правильные метки.
7. В остановленной записи кликните по номеру, введите новый. Enter сохраняет, Esc отменяет, уход из поля сохраняет. Меняется только выбранная фиксация, остальные номера не сдвигаются.
   Правый клик по подписи или устойчивому участку сигнала открывает также пункты:
   - «Delete» — исключить метку выбранной эпохи и убрать её зелёное выделение. Исходные границы HEOG и красные линии остаются, остальные номера сохраняются.
   - «Add» — открыть ввод номера для устойчивого участка без метки, в том числе ранее удалённого или находящегося до выбранного начала. Enter добавляет метку и зелёную область, Esc отменяет добавление. Новый интервал HEOG этим действием не создаётся.
   Для размеченной эпохи доступно удаление, для неразмеченной — добавление. Номер 0 означает оставленную для разметки эпоху с пока не заданной целью.
8. Для исправления начала — правый клик по подписи или по устойчивому участку сигнала → «Start sequence here». Эта команда заново нумерует выбранную и следующие фиксации, начиная с 41, и скрывает более ранние. Прежние ручные номера при такой перенумерации сбрасываются. Можно выбрать и более ранний участок, на котором зелёная заливка сейчас скрыта.

9. Для удаления лишней границы — правый клик непосредственно по красной линии → «Delete». Соседние участки объединяются от начала левого до конца правого, включая разрыв заливки возле удалённой линии. Сохраняется одна цифровая метка: левая, а если слева метки не было — правая. Остальные номера и красные границы сохраняются. Если обе области были исключены из разметки, номер не придумывается.

При выборе красной линии пункты «Add» и «Start sequence here» недоступны. Правый клик по цифровой подписи сохраняет прежний смысл меню для метки эпохи. Детектор при ручном удалении границы повторно не запускается; новые контролы не создаются. Объединение не заполняет пропуски отсчётов и не пересекает разрывы Sequence.

Если событий включения ноты нет или первое из них находится вне устойчивой фиксации, автоматический старт не выбирается. Красные линии остаются; начало можно указать той же командой правого клика. Программа не подменяет первую метку более поздним успешным срабатыванием.

Номера ручной разметки:

| Номер | Значение |
| --- | --- |
| 41, 43, 45, 47, 48, 50, 52, 53 | Существующие номера нот слева направо |
| 9–14 | Шесть квадратиков вне клавиатуры; назначаются вручную |
| 0 | Цель не задана / нельзя уверенно определить |

Для нот используются те же номера, что уже приняты в программе и отображаются на жёлтых событиях. Квадратики при дальнейшем анализе должны учитываться как фон, а не как шесть новых команд. На этом этапе классификатор и его классы не изменены.

Номера, объединённые области и ручное удаление красных линий сохраняются при перемотке, проигрывании и изменении размера. Редактирование доступно после StopPlay. Повторный Mark HEOG создаёт новый черновик; изменение порога очищает текущую разметку и тоже считается изменением. Исходный PHS не изменяется. Полный вывод классификатора и экспорт CSV в этот этап не входят.

## Сохранение

Для `SSVEPPlayIgn.phs` кнопка **Save** автоматически создаёт `SSVEPPlayIgn.analysis.json` в той же папке, без выбора имени. Оранжевая точка рядом с Save означает несохранённые изменения. Она появляется после построения разметки, изменения номера, добавления/удаления метки, объединения областей и изменения параметров HEOG. Перемотка, масштаб и проигрывание её не включают. Подтверждение прежнего номера и отмена редактирования по Esc тоже не создают изменений.

Сохраняется полное готовое состояние: все интервалы с исходными номерами отсчётов и QPC, стабильность, целевые номера и исключения, список оставшихся красных маркеров, параметры HEOG и версия формата. Для привязки к PHS проверяются частота дискретизации, названия каналов, частота QPC, число отсчётов, объём записанной части файла и начальная/конечная отметки времени. Название папки в привязку не входит: запись и её JSON можно переносить вместе.

При следующем открытии PHS программа восстанавливает это состояние без запуска Mark HEOG и без активации другой модели. Параметры HEOG подставляются в интерфейс без очистки загруженных интервалов. Автоматического сохранения нет.

**JSON можно удалить вручную.** Он не удерживается открытым. После переоткрытия PHS разметки не будет, останутся исходные ЭЭГ и записанные события. Отсутствие JSON допустимо и не вызывает его автоматического создания. Если файл удалён при открытой записи, текущая разметка остаётся в памяти до закрытия; повторное нажатие Save создаст JSON снова.

Успешный Save гасит точку. Перед закрытием приложения, открытием другой записи или запуском новой записи при наличии правок предлагается «Сохранить / Не сохранять / Отмена». Отмена сохраняет открытый файл и правки. Ошибка записи оставляет индикатор включённым и не позволяет закрыть запись при выборе сохранения. Прежний JSON заменяется только после полной записи нового временного файла.

Повреждённый, неподдерживаемый или не соответствующий PHS файл анализа не применяется; ошибка показывается в журнале SSVEP, а сама запись остаётся доступной.

## Короткие фиксации

Зелёным показывается вся найденная устойчивая фиксация начиная с выбранного начала обхода. Прежнее ограничение заливки объединением только полных окон, помещающихся внутри неё, снято. Поэтому фиксации короче секундного окна тоже видны и получают редактируемый номер. Искусственного растягивания через скачок HEOG или наложения на соседнюю фиксацию нет.

Это интервалы целевых меток, а не границы окон ЭЭГ. Длина окна, шаг, признаки, LDA и допуск команд не менялись. Отбор и привязка фактического выхода классификатора к этим меткам будут подключены на этапе второй кнопки; сейчас классификатор не перезапускается.

## Детектор HEOG

Алгоритм определения скачков сохранён. При DetectionWindowMilliseconds = 100 и частоте 500 Гц:

- HEOG сглаживается медианой из 5 отсчётов;
- вычисляется разность сглаженных значений через 25 отсчётов (50 мс);
- местный тренд разности оценивается медианой из 201 отсчёта;
- из разности вычитается тренд. Порог должен превышаться и исходной разностью, и остатком после удаления тренда, с одинаковым знаком.

Range задаётся в микровольтах. Записанные в вольтах значения сравниваются с RangeThresholdMicrovolts × 10⁻⁶. Постоянный уровень и линейный дрейф сами по себе меток не создают. Медиана подавляет одиночные выбросы.

Срабатывания с паузой не больше MinimumStableDurationMilliseconds (по умолчанию 200 мс) объединяются в один переход. Красная линия ставится в точке максимального перепада после удаления тренда. Вся область перехода, включая поддержку коротких фильтров, исключается из фиксаций. Устойчивый участок должен иметь длительность не менее MinimumStableDurationMilliseconds.

Границы и красные линии привязаны к исходным номерам отсчётов. Незначительный джиттер часов блоков не теряет метки и не разрывает фиксацию. Настоящий разрыв Sequence, нумерации отсчётов или недопустимое значение HEOG разделяют участки. Один интервал не превращается в несколько эпох из-за границ блоков файла.

## Интерфейс и StopPlay

Mark HEOG, Range, легенда, прогресс в statusStripMain, разделители, NumericUpDown для редактирования номера, контекстное меню, кнопка Save и индикатор изменений объявлены статически в Form1.Designer.cs. Пустое меню File удалено; его панель свёрнута. Панель кнопок и ползунок размещаются через Dock, чтобы тексты времени не перекрывались ползунком при изменении шрифта или размера окна. Контролы для каждой эпохи динамически не создаются: подписи рисуются отдельным слоем поверх графика. Изображения цифр создаются один раз и повторно используются при отрисовке. Диапазон редактора расширен до 53; Enter/Esc перехватываются в существующем ProcessCmdKey формы, пока фокус находится в редакторе. F6 и клавиши остальных контролов сохраняют прежнюю обработку.

Подписи событий в общей функции DrawEventLabelCore используют Consolas 10 pt с фиксированной шириной цифр, сглаживанием и привязкой текстуры к целым пикселям. Меню разметки, подсказки Save/индикатора и сообщения сохранения — на английском.

Код формы остаётся в Form1.cs, алгоритм и данные разметки — в HeogMarkup.cs, слой подписей — в GlScope.cs. Сохранение и проверка JSON вынесены в RecordingAnalysisStore.cs. Сторонних зависимостей нет; используются штатные средства .NET Framework.

Существующая логика StopPlay сохранена: при подключённом источнике живого маршрута SignalViewer возвращаемся к нему; без подключения показываем файл на текущей позиции. Проверяется наличие подключения, без таймаутов и проверки свежести. Старые методы отрисовки сигналов, их кеширования, открытия файла и остановки не переписаны.

## Проверка

На присланной SSVEPPlayIgn.phs (500 Гц, 28 каналов, 70,835 с), Range = 15 мкВ:

- детектор даёт те же 50 красных меток и те же границы устойчивых участков;
- фиксации 19,688–20,572 с (884 мс) и 29,150–30,112 с (962 мс) видны и подписаны без активной модели;
- первая метка включения ноты находится в фиксации 4,802–6,244 с; шесть более ранних фиксаций скрыты;
- проверены номера нот в прямом/обратном обходе, ручной ввод 50/53/12/0, Enter/Esc через очередь клавиатурных сообщений GUI, уход из поля, перемотка, изменение размера, проигрывание, перебазирование при смене масштаба времени и очистка по изменению порога;
- проверены перенос начала вперёд и назад, выбор скрытой ранней фиксации, статические пункты меню и отсутствие автоматической нумерации без подходящего старта;
- проверены реальный Designer, обработчики разметки и редактора вместе с настоящим OpenGL-рендерером; сигнал остаётся виден под слоем разметки;
- проверены удаление номера вместе с зелёным выделением, повторное добавление без дубликатов, отмена добавления по Esc, сохранение по Enter, правильный фокус после закрытия меню, блокировка отложенного добавления при запуске проигрывания и сохранение номеров остальных эпох;
- проверены правый клик по красной линии, точное преобразование позиции на экране в исходный отсчёт и различение красной линии / цифровой подписи;
- удаление линии в 6,610 с объединяет 6,350–6,578 с и 6,644–8,250 с в одну область 6,350–8,250 с с одной меткой 43; бывший разрыв заливки исчезает. После объединения метка остаётся редактируемой;
- проверены сохранение других номеров и границ, выбор правой метки при отсутствии левой, края сегмента, повторное удаление и запрет объединения через пропуски / разрывы Sequence;
- исправленная разметка сохраняется при перемотке, изменении размера, проигрывании и возврате к статическому просмотру;
- проверены Save через реальную кнопку Designer, запись и повторная загрузка всех правок, восстановление параметров HEOG и отсутствие повторного расчёта;
- проверены индикатор изменений, отсутствие ложного индикатора при просмотре или неизменённом номере, все три ответа в диалоге закрытия, ошибка сохранения и успешная повторная попытка;
- проверены ручное удаление JSON при открытом PHS и переоткрытие без разметки/автоматического создания файла, сохранение явно очищенной разметки и обработка повреждённого JSON;
- проверены замена предыдущего снимка, отклонение чужой записи/некорректных интервалов и маркеров, отсутствие временных файлов и неизменность байтов PHS;
- сохранены проверки детектора, целостности исходных отсчётов и существующей логики StopPlay.

Короткий участок 6,350–6,578 с (228 мс) при Range = 15 мкВ появляется между срабатываниями детектора в 6,288 и 6,610 с. Во второй точке перепад после удаления тренда составляет 15,4 мкВ — чуть выше порога. При 20 мкВ этого короткого участка нет, но также исчезает переход около 4,742 с. Это проверка данного фрагмента, не доказательство оптимальности порога для всей записи. Настройки порога и алгоритм автоматического детектора при доработке ручного редактирования не менялись.

Полная сборка и запуск приложения на Windows требуют исходного окружения: присланный архив не содержит CommonUnits, пакетов решения и части Properties. Проверки компонентов выполнены в изолированном окружении; архив содержит исходники, не исполняемую сборку.
